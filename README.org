* Overview

A bare-metal software synthesizer running on the STM32F411E-DISCOVERY.
Designed to be fun for a kid.

Status: October 2026. The codec is fully brought up and audio is live on
hardware: reset, the I2C control bus, the chip-ID read, the CS43L22 init, the
I2S3 data path, circular DMA, and a half-transfer/transfer-complete ping-pong
interrupt that streams the real engine as stereo. The engine runs in real time
on the MCU (full 8-step pentatonic melody, 2 KB DMA buffer). Host-side MVP work
(Phase 2) is still pending. The V1 control surface (8 pads + rotary encoder + 3
pots + SSD1306 OLED) is designed but not yet built; see "Controls (V1)".

* Goals

- Small, finishable embedded project
- Clean architecture separating engine from hardware
- Multi-platform from same codebase
- Fun for kids to use

* V1 Build Plan (step-by-step)

Work top to bottom; every step ends in an observable check so you always know
you are unstuck. Host steps (A) need no hardware. Keep the engine platform-free
(no stdio, no STM32 headers). Match the existing style: top-of-block declarations
and =/* */= comments. Every change must keep both =make cli= and =make= green
under =-Werror=.

** Work loop

- Host: =make cli && ./synth | aplay -f S16_LE -r 48000 -c 1=
- Hardware: =make && make flash= (board on USB ST-LINK). Debug with OpenOCD in one
  terminal and =arm-none-eabi-gdb synth.elf= + =target extended-remote :3333= in
  another. When dumping live state, vary the halt delay so it never lands on the
  same loop phase twice (a fixed =sleep= can read all-zeros on the =NOTE_REST=
  step).

** A. Engine API + filter types + audition (host)

1. =engine_set_step_note(e, step, note)= in =engine/engine.c=, declared in
   =Inc/engine.h=. Bounds-check =step=, set =steps[step].note= and
   =steps[step].enabled = (note != NOTE_REST)=.
3. =engine_get_step(e, step)= - return the =Step= (for the OLED).
4. Extend =FilterType= with =FILTER_HIGH_PASS= and =FILTER_NONE=. In
   =filter_process=: =HIGH_PASS= returns =sample - lp= (run the same one-pole LP,
   subtract); =NONE= returns the input unchanged.
5. =engine_set_cutoff(e, hz)= - thin wrapper over =filter_set_cutoff=.
6. Audition: add =uint8_t audition;= and =MusicNote audition_note;= to =Engine=.
   In =next_sample=, when =audition= is set, skip the step-advance block and drive
   =phase_inc=/=ramp= from =audition_note= (a rest = silence).
- *Verify:* =make cli= stays green and =./synth= still plays the same melody.
  Optionally drive the new setters from =platform_cli.c= to hear a change live.

** B. OLED bring-up (hardware)

1. Add =src/ssd1306.c= to =ARM_SRCS= in the Makefile.
2. Fix two driver bugs in =src/ssd1306.c=:
   - =ssd1306_data()= writes =len-1= bytes from =data+1= (drops byte 0) -> write
     =len= bytes from =data=.
   - =ssd1306_update()= sends column-set =0x10= twice -> first must be =0x00=.
3. In =platform_stm.c=, after =i2c1_init()=, call =ssd1306_init()=, then
   =ssd1306_draw_string(0, 0, "hello")= + =ssd1306_update()=.
- *Verify:* "hello" appears and the codec chip-ID read still succeeds (shared
  I2C1 bus: =0x3C= vs =0x4A=). Blank screen = wrong address jumper (some are
  =0x3D=).

** C. One pot -> live value on OLED (hardware)

1. Enable ADC1 on PA1; polled single conversion in the main loop.
2. Average a few samples, map 0-4095 to 40-240, show the number on the OLED.
3. Add slew/deadband so a noisy pot does not flicker the display.
- *Verify:* turn the pot, watch the value track on the OLED.

** D. Pads + encoder -> step / note on OLED (hardware)

1. Configure the 8 pad pins as inputs with pull-ups; scan + debounce (N stable
   samples), detect press/release edges.
2. Encoder on PB4/PB5: poll quadrature (or TIM3 encoder mode); a detent = one
   step through ={REST, C4, D4, E4, G4, A4, C5, D5, E5, G5, A5}=.
3. A pad press selects a step; show selected step + note on the OLED.
- *Verify:* each pad changes the step number; the encoder steps the note name.

** E. PLAY/EDIT state machine + audition (hardware)

1. Pad press -> set =e->audition=1= and =audition_note= to that step's note;
   release -> =audition=0=. The sequence pauses while held (audio keeps streaming).
2. The encoder calls =engine_set_step_note= and updates =audition_note=, so you
   hear the note change live.
3. OLED shows =PLAY= vs =EDIT=, selected step, note, and the 8-step pattern.
4. RT safety: the UI writes =Engine= while the DMA ISR reads it; wrap multi-field
   updates in a =PRIMASK= critical section.
- *Verify:* hold a pad -> loop pauses and the note sustains; turn the encoder ->
   pitch changes live; release -> loop resumes.

** F. Wave/filter cycle + volume (hardware)

1. Wave button: =engine_set_wave(e, (e->wave+1) % 4)=. Filter button: cycle
   =LOW_PASS -> HIGH_PASS -> NONE=.
2. Add =codec_set_volume(percent)= in =src/codec.c= (reuse =volume_to_reg=);
   write =MASTER_A/B_VOL=. Wire the volume pot to it.
3. Cutoff pot -> =engine_set_cutoff=; tempo pot -> =engine_set_bpm=.
4. Map pots: tempo 40-240, cutoff ~200-12000 Hz (log), volume 0-cap (80).
- *Verify:* each control changes its value on the OLED and is audible.

** G. Polish

1. Default boot pattern (so it makes sound on power-up).
2. Volume safety cap (e.g. 80).
3. Faceplate / case + labels; final demo.

* Board Change (April -> August 2026)

Originally targeted the STM32F446RE, which has two internal 12-bit DACs.
Now targeting the STM32F411E-DISCOVERY.

*** IMPORTANT: the STM32F411 has no internal DAC.

The F401/F411 "access line" omits the DAC peripheral entirely. The
32F411EDISCOVERY product page lists an "audio DAC with integrated class-D
speaker driver" - that is a *separate chip on the board* (Cirrus Logic
CS43L22), listed alongside the gyroscope and microphone, not a peripheral
inside the MCU.

Practical consequence: audio leaves the MCU over *I2S*, not via a DAC
register write.

*** Reference manual note

Chapter 14 "DAC" belongs to *RM0090* (F405/407/427/429). The correct manual
for this board is *RM0383*, which has no DAC chapter. Board-level pinout and
schematic live in *UM1842*.

*** Why stay on the F411 anyway

- The board is already on the desk and has a 3.5mm jack wired
- Repo is already half-migrated (=stm32f411_startup.c=, linker script matches
  512K/128K of the F411VE)
- Stereo 16-bit sounds better than 12-bit mono
- Retro character is an *engine* setting, not a hardware limitation, so
  nothing is lost by using a good converter

* Architecture

** The Core Principle

#+BEGIN_EXAMPLE
Hardware Input -> Hardware Layer -> Software Engine -> Hardware Layer -> Sound Output
#+END_EXAMPLE

The software engine is sandwiched between two hardware layers. It speaks only
in musical concepts, never in pins, registers or voltages.

** Layers

*** Engine (pure C99, zero platform deps)
- Oscillator
- Envelope (attack/release ramp; full ADSR deferred)
- Filter
- Step Sequencer
- Knows nothing about STM32, miniaudio, or any platform

*** Hardware Abstraction (HAL)
- Abstract interface between engine and platform
- Just function signatures both sides agree on
- Engine calls it, platform implements it

*** Platform Layer (one per target)
- =stm32/= - I2S + DMA + CS43L22 codec control over I2C
- =desktop/= - stdout pipe to aplay, later miniaudio

* Signal Path (F411E-DISCO)

#+BEGIN_EXAMPLE
engine -> ring buffer -> DMA -> I2S3 (SPI3) -> CS43L22 -> 3.5mm jack
                                   ^
                              I2C1 (config only, once at startup)
#+END_EXAMPLE

Two buses, two jobs:

| Bus  | Role            | Traffic                                    |
|------+-----------------+--------------------------------------------|
| I2C1 | Control channel | One-time setup: format, volume, power, mute |
| I2S3 | Data channel    | Continuous sample stream, DMA-fed           |

They fail independently, so they get tested independently.

* The Sequencer

** Scope (MVP)
- 8 steps (decided August 2026)
- Each step is a 16th: =samples_per_step = SAMPLE_RATE * 60 / (bpm * 4)=.
  8 steps = 2 beats = 1 s loop at 120 BPM.
- Pentatonic scale (no wrong notes, kid friendly)
- Each step has an on/off state and an assigned note
- Loops continuously

Note: =platform_cli.c= currently hardcodes a 5-note pentatonic loop; Phase 2
replaces it with the 8-step MVP pattern.

** Why Pentatonic
Almost any combination of notes sounds musical. A 7 year old cannot make it
sound bad. Perfect for a child bashing buttons enthusiastically.

** Controls (V1, planned)

Two states only:

- *PLAY* - the 8-step loop runs; the display shows the current step and pattern.
- *EDIT* - momentary: press-and-hold a pad to pause the loop and audition that
  step; release the pad to resume.

| Control       | Physical          | Action                                          |
|---------------+-------------------+-------------------------------------------------|
| 8 pads        | buttons (hold)    | hold -> EDIT that step; release -> PLAY         |
| Note          | rotary encoder    | selected step's note, =NOTE_REST=..pentatonic   |
| Tempo         | potentiometer     | 40-240 BPM                                      |
| Filter cutoff | potentiometer     | ~200 Hz - 12 kHz                                |
| Volume        | potentiometer     | codec master, hard-capped for safety            |
| Wave          | button            | cycle =(wave+1) % 4=                            |
| Filter        | button            | cycle =LP -> HP -> Bypass= (=type+1) % 3=       |
| Display       | SSD1306 OLED, I2C | state, values, 8-step pattern                   |

The note control folds step on/off into pitch: the bottom of its range is
=NOTE_REST=, matching the engine rule =enabled = note != REST=, so there is no
separate on/off control.

Filter select extends the engine =FilterType= from =LOW_PASS= to =LOW_PASS= /
=HIGH_PASS= / =NONE= (bypass). =filter_process= derives the high-pass as
=hp = x - lp=.

* Engine API

** Input side (musical events in)
#+BEGIN_EXAMPLE
set_step_note(step, note)
toggle_step(step)
set_tempo(bpm)
#+END_EXAMPLE

=Engine.steps[]= already stores ={note, enabled}= (see =Inc/engine.h=), so the
data model is ready. Only the mutators remain: =engine_set_step_note= and
=engine_toggle_step= (build plan step A). =engine_set_bpm= covers tempo.

** Output side (samples out)
#+BEGIN_EXAMPLE
fill_buffer(buf, n)   <- primary; DMA and miniaudio both want blocks
get_next_sample()     <- convenience wrapper over the above
#+END_EXAMPLE

The current =platform_audio_write(sample_t)= is one sample per call. That is
fine for a stdout pipe and unusable for DMA. The block form is the real
interface.

*** Caveat on =i2c.c=
Resolved (Sep 2026): the CS43L22 sits on *PB6 = SCL, PB9 = SDA* (AF4), not the
PB8 the OLED driver assumed. =src/i2c.c= now configures the pins from a
descriptor and exposes a single-byte write. It still hardcodes
=I2C1->CR2 = 16= (16 MHz PCLK1); raising the system clock later would silently
break the I2C timing, so revisit that when the clock tree changes.

* Engine Components

** Oscillator
Pure math function producing a sample value. Waveforms: sine, saw, square,
triangle. No platform knowledge whatsoever.

** Envelope (ADSR)
State machine in software. Scales oscillator output over time.
States: attack, decay, sustain, release. A linear attack/release ramp exists
today (=MAX_RAMP=); full ADSR is deferred.

** Filter
One-pole low pass, applied per sample. Currently =(1 - 2*fc/fs)^2= as the
coefficient, cutoff 4000 Hz. =HIGH_PASS= / =NONE= bypass are planned (build
plan step A).

** Step Sequencer
Array of 8 steps, each with a note and on/off state. Counts samples to advance
steps. Completely divorced from audio output.
